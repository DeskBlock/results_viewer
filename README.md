# FEM Frame Viewer

ローカルフォルダの連番画像を、最大4つの表示枠で比較・再生するブラウザアプリです。HTML・CSS・JavaScript を `index.html` にまとめており、インストールやビルドは不要です。画像はブラウザ内で処理し、外部サーバーには送信しません。

## 起動

フォルダ選択（`webkitdirectory`）に対応したブラウザで `index.html` を開いてください。

HTTP 経由で開く場合は、Python 3 が利用できる環境で次を実行します。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8000/` を開きます。

## 画像の選択と表示

1. 上部の「表示数」で1〜4を選びます。
2. 各枠の「フォルダ選択」で画像を含むフォルダを指定します。
3. スライダーや Step 入力、再生ボタンで表示を操作します。

画像ファイルはファイル名の自然順（例：`frame1.png`、`frame2.png`、`frame10.png`）に並びます。各枠の同じ順番の画像を同じ Step として扱います。ファイル名に含まれる数値を解析して対応付ける方式ではありません。

Step の総数は表示中のフォルダの最大画像枚数です。画像が足りない枠には「この Step の画像はありません」と表示します。各枠の上部には「フォルダ名 · 枚数 · 現在表示中のファイル名」を表示し、省略された文字はマウスを重ねて確認できます。

3 Step先まで画像を順に先読みし、現在・直前の画像とともにデコード済み画像を再利用します。Loop時は先頭への折り返しも先読みします。次の画像のデコードが完了するまで現在の画像を維持し、切り替え時の黒い画面を抑えます。

キャッシュは各枠で最大6枚、デコード後の推定容量64 MiBを目安に制限します。表示中と表示要求中の画像は保持するため、大きな画像では容量の目安を超えることがあります。元画像のファイルデータやブラウザ内部のメモリはこの容量に含みません。フォルダ変更・非表示化・構成復元・ページ離脱時には対応するキャッシュを解放します。

## 操作

| 操作 | 内容 |
| --- | --- |
| 先頭・前・次・末尾ボタン | Step を移動 |
| スライダー | 指定位置の Step に移動 |
| Step 入力 + Enter | 1〜総数の整数を入力して移動 |
| Play / Stop | 再生・停止 |
| Speed | 1 / 2 / 5 / 10 / 20 / 30 / 60 FPS（初期値10） |
| Loop | 最終 Step の次に Step 1 へ戻って再生を継続 |
| 左右矢印キー | 前・次の Step に移動 |
| スペースキー | 再生・停止 |

Loop は初期状態ではオフで、最終 Step で停止します。再生中も Speed と Loop を変更できます。Step 入力欄にフォーカスすると再生が止まり、Enter を押さずにフォーカスを外すと入力を取り消します。入力欄やボタン、境界線にフォーカスしている間は、その操作を優先して全体のショートカットを無効にします。

フォルダや表示数を変更すると再生は停止し、Step は先頭に戻ります。表示数を減らしても非表示の枠の画像は保持されます。

## 表示枠の調整

ブラウザの表示領域全体を利用し、画像の縦横比を維持して表示します。16:10を含む画面サイズに追従します。

- 1枚：全領域、2枚：左右、3〜4枚：2×2（3枚の場合は右下が空き）。
- 境界線をドラッグして左右の幅・上下の高さを調整できます。調整範囲は20〜80%です。
- 「均等に戻す」で両方の比率をリセットします。
- 境界線のダブルクリック、またはフォーカス中の Home キーで、その境界線を中央に戻します。
- 境界線にフォーカスして矢印キーを押すと、対応する方向に2%ずつ調整できます。

## 構成の保存と復元

「構成を保存（画像込み）」で JSON ファイルをダウンロードします。「構成を読み込む」でそのファイルを選ぶと、フォルダの再選択なしで復元できます。

保存する内容：

- 全4枠の画像データ・ファイル名・フォルダ名（非表示の枠も含む）
- 表示数、Step、Speed、Loop
- 左右・上下の分割比率

復元後は停止状態です。以前の画像入りJSONも読み込めます。Loop や分割比率がないファイルは、Loop オフ・均等配置で復元します。不正な構成ファイルの場合はエラーを表示し、現在の構成を維持します。

画像をBase64形式で含めるため、JSONは元画像の合計より大きくなります。保存するのはその時点の画像であり、元フォルダへの変更は自動反映しません。フォルダパスのみの保存・復元には対応していません。

## 動作上の制約

- 対応画像は、ブラウザが画像のMIMEタイプを付与し、デコードできる形式です。
- FPS は再生間隔の設定値です。表示要求中の画像の処理が完了するまで次のStepへ進まないため、先読みが追いつかない場合は再生速度が下がります。画像サイズ・枚数・端末性能・ブラウザの状態により、実際の表示速度は変わります。
- 大量の画像を含むJSONの保存・読み込みには、時間とメモリが必要です。
